# Attention/序列模型在推荐系统中的价值：三域实证完整记录与实践建议

**TopPrism RecSys Benchmark v0.9 · 2026-11-03 · 报告 v1.8 FINAL**
本文是给工程/研究团队的建议记录：我们把 28 次神经训练、5 套排序臂、10 份外部裁决的完整过程，压缩成一份"别人可以直接用"的东西。所有数字可复现（文末索引）。

---

## 一句话结论

**序列/attention 模型在推荐中的价值高度依赖域结构：电影域有真实增益（但主要来自模型结构而非"看内容"），时尚稀疏域无效，重复购买型零售域被零成本频次基线完全覆盖。三个域、同一协议，答案完全不同——脱离域结构谈"attention 有没有用"是伪问题。**

---

## 一、研究设计（为什么这个结果可信）

| 纪律 | 做法 |
|---|---|
| 三域同协议 | ML-1M（电影，稠密长序列）/ H&M（时尚，稀疏）/ Instacart（零售，重复购买 44%），同一评测协议、同一编码器实现 |
| 预注册 | 指标、门限、种子数、停止规则在跑之前冻结成文档（`protocols/`）；负面结果按协议如实接受 |
| 外部裁决 | 每阶段由独立评审逐轮审签（10 份裁决归档），措辞按证据强度分级，禁止过度归因 |
| 配对统计 | 用户级配对 Bootstrap CI95（Instacart n=20,000；ML-1M n=6,040），拒绝单点比较 |
| 泄漏控制 | Instacart 全程 t0/t1 时间契约：训练/候选/特征严格快照隔离 |
| ITT 原则 | 训练塌缩的臂按"训练失败"计入主结果，不悄悄丢弃（另做条件分析披露） |
| 塌缩审计 | 可疑输出走确定性重放 + 梯度活性探针 + 跨用户 top-10 重叠率三件套，机器判定真塌缩 |

## 二、核心发现（四个）

### 发现 1：attention 的增益被"结构包"携带，不是"看内容"

| 变体（ML-1M，6 种子配对） | 相对 MeanPool 增益 |
|---|---|
| 完整 SASRec | +0.145 |
| **只看位置的注意力**（Q/K 只吃位置 embedding，容量匹配） | **+0.134（恢复 91.5%）** |
| 均匀注意力（权重=1/n） | 小且不稳（6 种子 3 次塌缩） |

内容条件化 Q/K 的净增量只有 **+0.0124**（5 次点估计全正、4/5 显著）——**主角是位置编码+残差+FFN+LayerNorm 这套骨架，"动态分配注意力"只是配角**。
Instacart 上更极端：排序特征替换实验里，内容条件化相对位置版**无可检出增量（−0.0033，CI 跨零）**，位置版点估计甚至更高（0.1960 vs 0.1928）。

> 文献对照：Michel et al.（NeurIPS 2019）在 NLP 发现注意力头大量冗余；Dong et al.（ICML 2021）证明纯注意力算子若无残差/FFN 会秩崩塌。我们把这个"结构 vs 算子"问题第一次带进推荐场景并给出两域答案：**架构的性能优势 ≠ 最显眼的算子创造了优势**。

### 发现 2：频次地板——重复购买域里数数就是最优解

Instacart（ flattened next-item，44% 购买是重复商品）：

| 方法 | HR@10 | 备注 |
|---|---|---|
| **频次基线**（按用户历史购买频次排序） | **0.1934** | 零训练、毫秒级 |
| MeanPool 0.1461 / SASRec 0.1350 / GRU 0.1216 / HSTU 0.0800 | 全部更低 | |
| 最好的 attention+LGBM 混合（位置版） | 0.1960 | +0.0026，低于工程门槛且无配对确认 |

**当任务的信号大头是"再买一次买过的"，一维频次信号已经把可预测方差吃完了。**所有神经模型的"聪明"在这个域没有施展空间。

### 发现 3：更好的排序器 ≠ 更好的推荐系统（Hybrid 2×2）

把 SASRec 表示接入 LightGBM（用户命题"attention×LGBM 结合"）：

- 特征增量真实存在：M3−M1 = **+0.0155 [0.0115, 0.0197]**，且在无 SASRec 参与的候选池上依然显著（+0.0168）——表示信息独立于候选来源；
- 但**完整系统 vs 频次基线 = −0.0006 [−0.0048, +0.0036] 统计打平**：New 侧 +57 个命中被 Repeat 侧 −69 抵消；
- 局部能力的改善不保证系统超越强基线——**部署决策必须用系统级对照，不能用组件级增益**。

### 发现 4：训练稳定性是独立变量（常被忽略）

ML-1M 消融中：完整 SASRec 0/6 塌缩、位置版 1/6、均匀版 **3/6**（塌缩=所有用户同一 top10、loss 卡流行度水平）。Instacart 上同样两臂零塌缩——**塌缩率是"架构×域结构"的函数**。成功的消融读数不能外推为"平均因果效应"（ITT vs conditional 的差距在文献里很少被报告）。

## 三、给实践者的建议

### 决策树：你的场景要不要上 attention 序列模型？

```
第 0 步：算频次地板
  └─ 跑一个"按用户历史频次排序"的基线（半天工作量）
  └─ 若任务重复购买率高（零售/补货/订阅）：大概率到此为止，别往下走

第 1 步：看域结构
  ├─ 序列长且稠密（电影/音乐/内容消费，人均事件数百）：神经模型有空间 → 继续
  ├─ 稀疏（时尚购物，人均事件 <100）：先别上，先把特征工程做好 → H&M 结果
  └─ 重复购买主导：频次基线，结束

第 2 步：若上神经模型，先做廉价消融
  └─ 训一个"只看位置"的变体（改 Q/K 来源，几十行代码，成本≈完整版的 1/N）
  └─ 若它拿到 ≥90% 的增益 → 你的增益来自结构包，内容寻址可以不要
  └─ 这一步帮你看清"买这个模型到底买到了什么"

第 3 步：组件增益 ≠ 系统收益
  └─ 增益要对照你当前的产线基线（通常是频次/热度/规则），不是对照 MeanPool
  └─ 配对 CI，工程门槛事先定死（我们的门槛 +0.005，最终没过）
  └─ 算总账：训练 + 推理服务 + 维护 vs 数数的成本
```

### 红线清单（我们踩过或差点踩过的）

1. **禁止"组件赢了=系统赢了"的推理**——用 2×2 或至少"完整系统 vs 产线基线"的配对对照收尾。
2. **禁止用 MeanPool 当"传统方法"的替身**——频次/热度/规则基线才是产线对手；不跑频次基线的论文结论在零售域直接作废。
3. **禁止单种子结论**——我们 ML-1M 阶段一曾把单种子的正向读数当发现，扩种子后缩水一半；最少 3 种子配对起步。
4. **禁止丢弃训练失败的臂**（除非预注册说了条件分析）——塌缩本身就是发现。
5. **禁止跨域搬结论**——"ML-1M 上有效"推不出"零售上有效"；两域效应量不可合并（估计量不同质：端到端 vs 精排特征是两种东西）。
6. **引用文献时核对"对手是谁"**——大量已发表增益的对照基线是弱化的（见 Dacrema et al. 2019）。

### 协议纪律（可直接抄的清单）

- 预注册文档先行：指标/门限/种子/停止规则/负面结果处置，评审后再跑；
- 用户级配对 Bootstrap，报 CI 不报单点；
- ITT 主结果 + 条件分析附注；
- 塌缩审计三件套（确定性重放/梯度探针/用户间重叠率）；
- 时间契约（Instacart 类任务：特征可用性快照，防泄漏）；
- 外部裁决 + 措辞分级："未观察到增量"≠"证明了没有"。

## 四、局限与适用边界（诚实披露）

- 三个域 ≠ 全部域：冷启动、新品发现、内容驱动电商未测——那些场景重复信号弱，attention 的价值空间**没有被本文否定**。
- 位置版变体仍含内容相关的 Value 投影/FFN/残差——我们**不能**把增益单独归因于"位置编码"或宣布"attention 算子本身不必要"。
- Instacart 候选池仍由原始 SASRec 召回参与构造——证明的是"A2 特征可替代 A0 排序特征"，不是"系统可整体移除内容条件化模型"。
- 单 GPU（3080 Ti 20GB）、≤2.9GB VRAM、无超参搜索（统一小预算）——规模化配置下结论不自动成立。
- 部分模型评估横跨官方 train/test 边界（统一施加、已披露）。
