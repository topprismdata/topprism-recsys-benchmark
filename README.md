# TopPrism RecSys Benchmark v0.9

Do sequential models (attention-based recommenders) actually add value in recommendation systems? This repository answers that question with a three-domain, pre-registered, GPT-adjudicated benchmark.

**Final report:** [`docs/superpowers/reports/2026-10-26-report-v1.0.md`](docs/superpowers/reports/2026-10-26-report-v1.0.md) (v1.8 FINAL — all sections GPT-signed)

## Headline results

| Question | Answer | Evidence |
|---|---|---|
| Does SASRec beat simple baselines? | **Only in dense-movie-data (ML-1M)**: 0.228 vs MeanPool 0.084 (2.8×); in H&M fashion, all neural encoders within ±0.001 of GBDT (ns); in Instacart groceries, a trivial **repeat-frequency baseline (0.1934) beats every neural model** | §4–§7 |
| Does attention representation × LightGBM work? | **A better ranker, not a better system**: SASRec features add +0.0155 [0.0115, 0.0197] to LightGBM ranking, but the full hybrid ties the frequency baseline (−0.0006, CI crosses zero) | §8 (2×2 + 4 paired effects) |
| Is the gain carried by content-conditioned attention? | **No**: a PositionOnlyAttn control (Q/K from positional embeddings only, capacity-matched) recovers 91.5% of SASRec's end-to-end advantage on ML-1M, and on Instacart shows *no* additional reranking gain over full SASRec (−0.0033, CI crosses zero) — point estimate actually higher | §9 (operator ablation, phases 1–2) |
| Deployment verdict | **NO-GO** on all tested configurations; the trivial frequency baseline remains the right production choice for repeat-purchase retail | §8–§9 signing |

## Three domains, one protocol

| Domain | Task | Winner | Key structure |
|---|---|---|---|
| ML-1M (movies, dense) | next-item HR@10 | SASRec 0.2280 | long sequences, content matters a little (+0.012) |
| H&M (fashion, sparse) | MAP@12 | GBDT 0.0404 | sparsity kills sequence signal |
| Instacart (grocery, repeat-heavy) | flattened next-item HR@10 | frequency 0.1934 | 44% repeat purchases; frequency floor absorbs everything |

## Methodology

- **Pre-registered protocols** (`protocols/`, `.superpowers/sdd/.../PREREG-*.md`): metrics, gates, seeds, and stop rules frozen before runs; negative results accepted as-is.
- **Paired bootstrap** CIs at user level (n=20,000 Instacart / n=6,040 ML-1M).
- **Controlled ablation ladder**: full SASRec → PosOnlyAttn (Q/K positional-only, capacity-matched) → UniformAttn → MeanPool; collapse audited by deterministic replay, gradient-activity probes, and cross-user top-10 overlap.
- **t0/t1 time contract** on Instacart: LGBM trains/predicts under a strict feature-availability cutoff (leakage-controlled).
- **External adjudication**: every stage reviewed and signed off in independent GPT review sessions; 10 verdict transcripts archived under `.superpowers/sdd/`.

## Data

Raw data is not included. Obtain and place under `data/`:

- **ML-1M**: [MovieLens 1M](https://grouplens.org/datasets/movielens/1m/) — `data/ml1m/`
- **H&M**: [Kaggle H&M Personalized Fashion Recommendations](https://www.kaggle.com/competitions/h-and-m-personalized-fashion-recommendations) — `data/hm/`
- **Instacart**: [Kaggle Instacart Market Basket](https://www.kaggle.com/competitions/instacart-market-basket-analysis) — `data/instacart/raw/`

`scripts/preprocess_instacart.py` builds the 5-core flattened sequences (20,000-user sample, seed 42) used by the Instacart experiments.

## Reproducing

Python 3.10, single GPU (all experiments ran on one RTX 3080 Ti 20GB; ≤2.9GB VRAM per model).

```bash
pip install -e .  # or: pip install torch lightgbm numpy scipy scikit-learn
pytest tests/

# Section 9 phase 2 (Instacart feature substitution)
python scripts/run_instacart_t0.py          # t0-cutoff encoder assets
python scripts/run_instacart_v4_combined.py # v4 encoder assets
python scripts/hybrid_v2c_ablation_m3.py    # 5-arm LGBM substitution + paired CIs
```

Large intermediate caches (co-occurrence matrices, LGBM feature blocks) are excluded from the repo and regenerated by the scripts.
